# ModelDesk 2.13.1：长剧本绘图交接修复

## 故障原因

项目群在将审核定稿交给绘图者时，直接拼接完整剧本、角色职责和执行记录。实际失败任务的绘图输入为 18,530 字符，超过媒体适配器的 16,000 字符限制，因而在发送请求之前失败。界面原先将此错误统一显示为“所选绘图模型调用失败”，重试还会增加重复的图片失败卡片。

## 修复行为

- 短提示词直接调用用户选定的图片模型。
- 长材料交给本群统筹模型整理为绘图说明，完整审核稿作为输入，保留人物、画风、情节转折、结尾及限制条件。整理过程没有工具执行权限。
- 绘图说明先做长度与完整性检查，再发送给原先选择的图片模型。不会偷偷更换提供商。
- 每个步骤保存原始材料哈希、绘图说明、整理模型和实际绘图模型。相同输入重试时复用说明；材料变化或缓存损坏时重新整理。
- 同一图片槽位只显示一张进度卡，内部保留尝试记录；具体错误安全地显示在卡片上。取消任务不会显示为绘图失败。
- 上游服务异常、认证失败、配额限制及内容审核拒绝分别提示。只读取固定的错误代码，不公开上游消息、凭据或链接；内容审核拒绝不会触发跨提供商重试。
- 只有实际图片通过校验并保存后才算交付成功；此修复不代表下游视频自动通过验收。

## 验证

回归覆盖长审核稿、结尾保留、精确模型路由、说明缓存、缓存篡改、重复卡片、超长或截断说明、取消以及错误信息脱敏。真实验收使用原失败任务的完整审核稿和原配置 `gpt-image-2.5`。

原失败输入 18,530 字符，经统筹整理为 3,091 字符，实际返回并保存 1 张 1,672 × 941 PNG（3,313,902 字节）。已查看图片，内容为狮子与蚂蚁的九格故事分镜；这是一张分镜图，并非九张独立图片，也不代表视频已完成。

验收过程中另外观察到一次网关 TLS 连接中断，以及另一条独立绘图请求的 `moderation_blocked`。前者恢复连接后成功返回上述图片；后者保留为拒绝，没有更换模型绕过。平台修复不能保证提供商始终在线或接受每个请求。

图片请求仍使用原先配置的模型及 Images API；接口格式参考 [OpenAI 图片生成接口](https://developers.openai.com/api/reference/python/resources/images/methods/generate)。
