# 项目群聊与 Muse 使用指南

项目群聊用于让不同模型围绕同一个项目持续协作；Muse Mac 作为独立的外部智能体接收任务，回复经你选择后再交给群内成员讨论。两种入口保留各自的成员、运行状态和来源记录。

## 创建一个长期协作群

1. 在顶部选择或新建项目，进入左侧「项目群聊」。
2. 填写群聊名称，例如「发布前代码审查」。选择已有协作组，或点击「新建组」，保存 2–4 位使用不同模型的成员及职责，再点击「创建群聊」。
3. 在「发送给」选择「@所有成员」或指定成员，填写任务，点击「发送消息」。选中的成员按群成员顺序接力，每位成员能阅读本轮此前成员的发言。
4. 后续直接追问。每个群分别保存记录、草稿、收件成员和上下文设置；切换项目、群聊或刷新页面后可以继续。较早记录通过「查看更早的消息」打开。
5. 使用回复旁的复制按钮，或「查看本轮成果」打开右侧成果面板，预览和导出本轮输出。

群聊使用建群时冻结的成员和职责。之后编辑协作组不会改变这个群；需要另一套成员时，创建新群。Grok 等模型必须先由当前模型连接实际提供，保存名称不会建立账户连接。只检查本轮被指定回复的成员是否可用。

输入区支持图片、文件和明确选择的项目资料。「上下文与工具」中可调整最近对话轮数、知识、记忆及允许的工具；默认使用最近 12 轮，长内容会按预算截断。保留完整历史不代表每次调用都读取全部历史。不同群聊的对话分别引用；由你主动选择的项目共用资料仍可用于多个群。

## 交给 Muse，再交给协作组

1. 在这台 Mac 安装并登录 **Muse Mac**，打开可输入的 Muse 窗口。展开群内「Muse Mac · 本机桥接」，点击「检查连接」。桌面版也提供「打开 Muse」。
2. 如果显示需要授权，在「系统设置 → 隐私与安全性 → 辅助功能」允许实际运行的 ModelDesk 原生桥接程序，再检查连接。电脑须保持解锁，Muse 窗口须可访问。
3. 在「交给 Muse 的任务」填写完整要求，点击「发送给 Muse」。例如：“调研这三个方案的实现限制，给出可核对来源，并列出需要人工确认的事项。”
4. 等待状态变为「已读取回复」。可以复制回复、打开原始 Muse 会话，或导出 Markdown / JSON。Muse 要求登录、确认权限或补充信息时，需要你在 Muse 中处理。
5. 点击「使用 Muse 回复继续讨论」。这一步只选择来源；在群聊输入框补充“请审查来源并提出实现建议”等要求，选择接收成员，再点击「发送消息」，才会调用群内模型。

每次新任务都创建一个独立的 Muse 会话，并关联当前项目和群。自动操作会切换 Muse 窗口；发送期间避免同时在 Muse 输入或切换会话。如果未能确认新会话或送达，会保留待核对状态，不自动再发一遍。

当前桥接只发送该输入框内的**文本**。群历史、图片、附件、项目文件夹、知识库和工具设置不会自动传给 Muse。需要引用资料时，先整理为明确的文本要求；不要把群内添加附件误认为已经上传到 Muse。Muse 自己的连接器、账户记忆和权限继续由 Muse 管理，ModelDesk 的项目范围和独立会话不能隔离 Muse 的账户级记忆。

只能引用当前项目、当前群中已确认完整的 Muse 回复。群任务保存当时的回复副本、来源任务、Muse 会话链接和全文指纹；引用最多保存 8000 字符，实际输入预算可能进一步截断并标明。原始记录仍可单独导出。引用内容作为外部材料，不授予新的工具权限，也不会把 Muse 改名成群里的某个模型。

## 理解状态与恢复

| 页面状态或操作 | 含义与下一步 |
| --- | --- |
| 排队等待 / 正在发送 | 同一个原生 Muse 账户依次处理任务，最多同时保留八个待处理或观察中的任务。 |
| 正在观察回复 | 已确认送达指定会话，正在读取回复。默认观察时限为十分钟。 |
| 需要你处理 | Muse 正在等待确认或补充信息，或回复缺少可核对的结束标记；先查看提示和原始会话。 |
| 已读取回复 | 在对应会话观察到本任务的助手回复和结束标记，且没有继续生成或等待确认。表示回复边界已确认，不证明事实正确或外部操作成功。 |
| 送达或回复未确认 / 观察已中断 | 记录和已读内容保留。先在 Muse 核对已有任务；服务重启、超时或窗口异常不会自动重发。 |
| 停止本地观察 | 停止 ModelDesk 轮询。已送出的 Muse 云端任务可能继续，需在 Muse 中自行停止；仍在本地队列且尚未发送的任务会移出队列。 |
| 继续观察原会话 | 仅重新读取已确认送达的同一个会话，不发送新任务，也不自动批准 Muse 操作。没有确认会话的任务不能使用此操作。 |

ModelDesk 会在任务文本后加入专属回复结束标记。它用于判断这条回复是否已经结束，不能代替对网页来源、文件落盘、代码测试或其他操作的独立核查。只有部分内容时会明确显示，不将它当作完整交付传入群聊。

## 实现与部署边界

这条集成通过本机 macOS 辅助功能操作已经登录的 Muse 窗口。它不是 Muse Code SDK，也不通过给 GPT/Gemini 添加 Muse 名称来模拟接入；不会读取或复制 Muse 登录凭据、浏览器 Cookie，也不调用私有认证接口。

| 组件 | 职责 |
| --- | --- |
| `backend/groups.py` | 保存群和冻结成员，校验项目范围，创建群消息，冻结明确选择的 Muse 引用。 |
| `backend/muse_bridge.py` | 持久化任务、串行队列、发送前记录不确定状态、核对回复、恢复观察和导出。 |
| `desktop/native/MuseBridge.swift` | 固定的原生窗口探测、发送和读取动作；只返回当前任务需要的状态与文本。 |
| `frontend/src/components/GroupWorkspace.jsx` / `MuseDesktopPanel.jsx` | 群历史、成员选择、资料、Muse 任务状态和显式回复引用。 |

群记录位于本机 `data/groups/`，Muse 任务与已读取内容位于 `data/muse/`；这些用户数据不进入 Git。Muse 的 `POST /api/muse/tasks`、停止和继续观察接口只接受受支持的本机页面来源与 loopback 客户端。观察时同时核对任务 ID、已确认会话 URL、助手角色和结束标记；仅打开页面或读到其他会话文字不足以完成任务。

原生桥接要求 macOS、Muse Mac、当前电脑的有效登录、辅助功能权限以及本地 ModelDesk 服务。开发环境可运行 `npm --prefix desktop run build:muse` 编译固定辅助程序，需要 Xcode Command Line Tools；正常应用打包命令会包含这一步。复制源码或应用包到另一台电脑不会迁移账户登录和系统授权，应用更新后也可能需要重新授权。现有本地网关、CAMEL/CrewAI 环境和相邻 `llm-tools` 的部署要求仍然适用。

状态机、项目范围、停止/恢复及回复引用由自动测试覆盖；真实原生窗口发送、读取和打包版本的验收以 [功能与验收表](CAPABILITIES.md) 的本轮记录为准。
