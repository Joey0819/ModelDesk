# 图文、视频与媒体交付 Harness

ModelDesk 2.9.0 · 2026-10-15

目标是把用户描述变成可查看、可下载且带来源的成品。媒体交付 Harness 负责需求识别、生成能力路由、受限执行、文件校验、正文与媒体绑定，以及最终完成状态。它在现有项目群和自动交付上工作；不会因为一个模型写出“图片已生成”就将任务标为完成。

## 快速操作

1. 在项目中保存协作组，选择统筹模型与成员，并应用到当前群。
2. 保持「自动完成」和「@协作组」。在「成果形式」选择「按要求自动」「仅文字」「图文并茂」或「视频成果」。
3. 展开「生成设置」，选择配图数量与工具；「实际生图能力」从当前登录网关和已启用的 API 连接读取候选。
4. 写明成品要求，例如：「写一篇给初学者的 AI 编程公众号文章，正文约 1200 字，配两张原创说明图，图注说明它们是概念插图，不要冒充实际软件截图。」
5. 时间线会显示实际生成任务。右侧呈现文章与真正保存的配图，视频使用播放器。可以分别下载媒体，或下载完整 ZIP。

「按要求自动」根据本轮提示判断是否需要图片和视频；明确选择的成果形式优先。当前直接生图每轮安排 1–4 张；要求更多图片时不能以较少图片冒充完成，缺失数量会保留在交付限制中。

同一轮需要不同工具分别负责图片和视频时，将「成果形式」设为「按要求自动」、「生成工具」设为「自动选择」，然后写清各自分工，例如：「写一篇图文并茂的文章，Gemini 生成两张原创图片，Muse 制作一个配套视频。」Harness 会分别绑定图片与视频的提供方，收集各自的实际产物后再整理到同一份成果中。

需要 Muse 时，在群内添加 `muse` 类型执行成员。视频任务由 Mac 上可用的 Muse 执行；手机不能操作 Mac 的 Muse 窗口。已有群若只有模型成员，选择 Muse 不会凭空创建或授权原生执行器。

## 能力与认证

| 路径 | 实际调用方式 | 验收边界 |
| --- | --- | --- |
| 已有 OpenAI 登录网关 | 当前网关提供的图像模型及 Images 生成端点 | 本机已从 `gpt-image-1.5` 取得真实图片；不意味着任意 GPT 聊天模型自动有生图工具 |
| 已有 Gemini 登录网关 | 图像模型的兼容多模态响应 | 本机已从 `gemini-3.1-flash-image` 取得真实图片；普通 Gemini 文本模型不等同于图像模型 |
| 已保存的模型 API | 按模型族适配 Images、兼容图像响应或 Gemini 官方 `generateContent` | 需要连接实际支持该协议与模型；保存 Key、列出模型或文本测试通过不等于生图通过 |
| Muse 原生 Agent | 当前任务独立会话、真实送达与回复边界、实际资源下载 | 本轮真实媒体通过校验后才计入完成；回复文字和旧文件不算新媒体成果 |

自动选择优先使用已经取得实际图片的可用候选；混合需求可从提示中分别指定图片和视频提供方，例如 Gemini 负责图片、Muse 负责视频。用户在界面明确选择 OpenAI、Gemini 或 Muse 时，该选择仍具有约束力；当前视频生成适配仅支持 Muse，明确指定不支持的视频提供方会保留缺失项，不会静默改成 Muse 执行。模型能力列表中的「待验证」表示候选能力；「已实测生图」表示该别名曾返回并保存过实际图片，不保证以后每次调用或所有账号都成功。

仅在生图提供方和模型均未固定时启用自动替代：首选失败后最多再试一个不同提供方，总计最多两个，不逐个遍历所有模型。显式界面选择或提示中绑定的提供方保持不变；失败仍据实保留，不把其他提供方的结果冒充该选择。

这些认证沿用当前本机网关和 API 连接。适配器在发起请求时解析凭据，任务成果只保存相对本地媒体地址与来源信息。它不复制 ChatGPT / Gemini 网页界面，也不把订阅产品中的全部工具描述成已经接入。

供应商官方文档：[OpenAI Image generation](https://developers.openai.com/api/docs/guides/tools-image-generation)、[Gemini Image generation](https://ai.google.dev/gemini-api/docs/image-generation)。这里引用的是供应商能力说明；本项目已验证的模型和调用路径以上表及实际任务记录为准，不包含官方接口的所有生图编辑参数、工具或工作流。

## 从需求到成品

```text
成果形式 + 本轮需求
        ↓
图片数量、视频需求、生成工具契约
        ↓
群成员讨论与实际 Agent 分工
        ↓
生图模型调用 / 当前 Muse 任务媒体
        ↓
下载、格式解码、容器校验、大小与来源绑定
        ↓
真实媒体清单 + 完整正文排版
        ↓
完成状态 / 部分成果与缺失项
```

- `backend/delivery_harness.py`：媒体需求、能力路由、配图分工、原生结果收集与正文绑定。
- `backend/media_providers.py`：当前能力发现、供应商协议适配、实际生成与验证记录。
- `backend/delivery_media.py`：私有文件存储、受限 URL 下载、内容读取和离线导出。
- `backend/group_delivery.py`：模型讨论、已授权执行 Agent、媒体生成与完整正文的统一生命周期。

这层 Harness 与已有 LangGraph 多阶段协作共用项目、任务与成果边界；没有为了媒体生成另外引入一套未经验证的 Agent 框架。

图片只从真实生成响应或本轮原生任务的实际资源中取得。最终正文中的媒体标记绑定本任务保存的文件；未登记的图片地址不会以托管图片展示。模型可以规划插图，但不能用自己编造的 URL、示例位图或“已完成”文字填满媒体清单。

Muse 资源必须来自同项目、同群、同一父任务的已确认回复，且属于当前执行任务。公开 HTTPS 地址仍不可信，需要重新下载并验证；网页链接、HTML 预览页或受登录保护但无法下载的附件不会直接计为媒体。当前导入不抓取本机或私有网络地址。

## 真文件、持久保存与读取

- 图片支持单帧 PNG、JPEG、WebP，由 Pillow 验证并实际解码；每张最多 25 MB，单边最多 16384 像素、总像素最多 4000 万。
- 视频支持 MP4、WebM；校验容器头与媒体数据结构，当前机器可用 `ffprobe` 时以受限协议和时间检查真实视频流。仅有音频、损坏文件、HTML 或一段视频说明均不通过。格式与来源校验不替代对视频创意细节的审核。
- 每任务最多 12 份媒体、合计 200 MB，单视频最多 150 MB。下载流、重定向和时间均受限；每次跳转重新校验公开目标，并固定已校验 IP、Host 与 TLS SNI，不转发账户凭据。
- 私有目录为 `data/delivery-media/<任务 UUID>/<媒体 UUID>/`；目录权限 `0700`、文件权限 `0600`，完整资源通过目录替换原子发布。拒绝符号链接、硬链接和路径越界。
- 媒体清单保存任务、项目、媒体种类、MIME、文件名、大小、SHA-256、提供方、模型、位置和图注；原生结果可附来源任务 ID。临时供应商下载 URL 不作为公开媒体地址。
- 每次读取都先查真实任务并核对项目范围，再校验文件大小与 SHA-256。无项目群只能以无项目范围读取，不能借由省略范围访问已有项目。服务重启后使用原文件与来源清单，不重新生成图片。

`GET /api/media/capabilities` 返回当前候选和已有实际验证状态。媒体内容位于 `/api/media/jobs/{job_id}/assets/{asset_id}/content`；有项目时必须携带匹配的 `project_id`，下载使用 `download=1`。这些是既有本地服务与已配对手机的内容路由，没有提供任意文件上传或通用 URL 代理。

## ZIP 成果包

`GET /api/media/jobs/{job_id}/bundle` 从该任务的最终 `delivery.media` 清单取得已验证文件，不获取正文中任意外部 URL。包内包含：

- `index.html`：正文、图注、图片和视频的离线预览；原生 HTML / 脚本作为转义文字，外部图片不加载。
- `article.md`：正文中的托管媒体地址改成可携带的 `media/` 相对路径。
- `media/`：实际图片与视频字节。
- `manifest.json`：交付状态、缺失项、文章指纹和每份媒体的来源与内容指纹。

导出逐项核对媒体归属和文件完整性，清单不匹配或媒体损坏时拒绝打包。未被最终交付清单选中的其他任务文件不会混入 ZIP。复制 Markdown 不会把图片变成图片字节；需要完整携带媒体时使用 ZIP。

平台的 JSON 数据备份保存配置、任务历史与媒体元数据，**不包含生成图片或视频的实际字节**。将 JSON 导入其他安装不会同时迁移媒体文件；需要携带、分享或离线保留图文和视频成果时，请另外下载该成果的 ZIP 包。

## 2.9 现场验收

2026-10-15，本机实际完成 Gemini 两张配图文章和 OpenAI 单张配图文章，两条路径都取得真实生成图片。完整混合验收还完成了「正文 + Gemini 图片 + Muse 原生视频」：群内 Muse 子任务实际完成，原生视频附件受控下载，与 Gemini 实际图片一起经过校验、持久保存和正文组合，最终交付无缺失项，支持携带真实媒体的 ZIP 成果包。

旧首轮生成失败继续保留部分交付状态；它促成了自动生图最多两个不同提供方的有界替代，后续成功不会改写旧记录。完整交付说明本轮取得了要求种类和数量的实际媒体，不意味着文章事实、画面创意细节、视频情节或其他外部动作已经被人工审核。

## 完成标准与失败处理

只有同时取得要求的正文和足量实际媒体，任务才可能标为完整。缺少图、未下载到 Muse 视频、调用失败、正文截断或执行未确认时，保留已完成内容并列明缺失项。不能用截图、模型自述、HTTP 200、模型目录或配置状态替代实际媒体成果。

自动调用仍受本次用户入口授权、固定成员类型、手机限制与取消控制约束。原生窗口需要 Mac 解锁、Muse 登录与辅助功能权限。停止本地观察不能保证取消已经发生的 Muse 云端操作；服务重启不会自动重发不确定的原生任务。

代码修改与测试保留原来的隔离副本、命令证据、独立审阅和人工审批；媒体生成不会获得自动合并、推送 GitHub 或对外发布文章的权限。

ModelDesk 仍保留 ChatHub / MultiBot 的原版入口和各框架自身的运行要求；本次媒体 Harness 不代表五个上游项目的全部功能或任何供应商的全部能力已经完整内嵌。
