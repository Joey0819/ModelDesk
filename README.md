# ModelDesk

**A local workspace where LLMs and executable Agents collaborate in project groups.**

把模型、执行 Agent、项目资料、代码审查和最终成果放在同一个工作区。你可以指定一个 LLM 担任 **统筹模型（Ruler）**，让它组织分工、调用群内 Codex、Claude Code、Muse 或已配置的 MCP Agent，以及可用的生图模型，再把真实正文、图片与视频整理成成果，并按要求生成 Word、PDF 或独立网页。

**当前桌面版本：2.21.0** · macOS / Apple Silicon · 中文界面 · 本机服务与私有手机入口

Muse 角色可绑定 Skills，长技能由统筹模型转换为创作指引，并保留原版本与实际发送内容。Lemo 的代码渲染由 Codex 执行；Muse 使用自身创作能力。详见 [2.13.3 Skills 接入与验收](docs/MODELDESK_2133_SKILLS.md)。

之前的真实协作验收与已知限制：[2.13.2 系统验收](docs/MODELDESK_2132_SYSTEM_ACCEPTANCE.md)。

ModelDesk 基于 [Karpathy 的 LLM Council](https://github.com/karpathy/llm-council) 扩展，保留独立回答 → 匿名互评 → 主席综合的三阶段流程，并复用 CAMEL、CrewAI 和 LangGraph 的执行能力。原项目说明见 [上游 README](docs/UPSTREAM_COUNCIL.md)。

## 从项目群开始 / Quick start

1. **创建项目**：添加图片、文件，或关联本地文件夹。代码执行需要关联一个已有提交且工作区干净的 Git 仓库。
2. **设置团队**：从「协作任务 → 自动协作」进入，点「新建组」，可套用文章、视频或代码分工模板并修改角色。也可打开「Agent 与连接 → 项目 Agent → 成员与分工」，选择统筹模型，为成员设置名称、类型与职责。需要 Grok 或其他模型时，先到「模型连接 / API Key」添加连接。
3. **描述成果**：保存协作组并新建项目群；修改已有群时，保存后点击「应用到当前群聊」。打开输入框上方的「任务设置」，选择「自动完成」，在「成果形式」选择「按要求自动」「仅文字」「图文并茂」或「视频成果」；「生成设置」可选配图数量、生成工具并查看实际生图能力。
4. **自动协作**：发送完整的交付要求。统筹模型把需求转为验收项与依赖计划；独立步骤并行执行，后续成员接收前置实际成果。Harness 按需求调用可用生图模型或 Muse，校验文件、组装正文并逐项审查。时间线显示任务、失败与缺失项；右侧呈现正文、实际配图和视频播放器。只想交流时切换「仅讨论」；也保留 @ 单个 Agent 的手动派发入口。
5. **审阅与交付**：可直接要求“生成 Word 和 PDF，采用报告版式”，或在「任务设置 → 交付文件」中选择格式与版式。完成后在右侧下载实际文件；已有成果也可点「导出」生成 Word、PDF 或独立 HTML。仍支持复制、Markdown、单份媒体和 ZIP 成果包。代码补丁需通过独立审查和人工合入审批。
6. **从飞书交代任务**：在「Agent 与连接 → 飞书远程」配置自己的飞书企业自建应用，把获准的聊天绑定到一个项目群。机器人通过官方长连接接收任务，完成后向原聊天回传结果与文件；不需要公开本机端口。没有自建应用时，先按页面指引创建和发布，再验证实际收发。

每个协作组可保存 **2–4 名成员**，统筹模型单独选择；LLM 成员与统筹合计最多使用四个不同模型。群聊历史、草稿、成员职责和资料按项目保存，同一个模型也可以担任不同角色。

## 2.21：固定项目记忆、长期 Agent 任务与真实交接

- **直接编辑项目记忆**：项目群输入框上方新增「项目记忆」。约束和已确认决策可固定到项目，自动完整带入新任务；保留版本历史，可恢复旧内容到编辑区。每个任务冻结当时版本，后续编辑不改写执行中的要求。固定记忆只属于当前项目，最多20条、合计8000字符。
- **外部 Agent 在后台执行**：支持 MCP 官方 Tasks 扩展的服务可返回任务标识。ModelDesk 保存原任务、按服务间隔查询、断线退避、重启续接；等待答复时显示表单，取消先保存意图并等远端确认。普通同步 MCP 服务仍兼容。已派发但未确认的调用不会重复发送。
- **前后成员能继续接力**：上游恢复后，原计划中有证据证明从未派发的下游 Agent 可以继续首次执行；已有回执只核对和回收。代码审阅实际读取通过指纹校验的补丁，超长或敏感内容明确标注，不再只交给审稿人一个文件名。
- **修复真实交付故障**：明确绑定的绘图模型遇到 HTTP 429/500/502/503/504 时有界重试，同一插图不悄悄换模型；已生成的图片继续保留。Muse 输入时临时关闭编辑器的智能引号并恢复设置，发送前逐字核对原始任务；已确认未发送的原草稿支持手动恢复。
- **飞书直接交代任务**：一个机器人绑定多个项目群，无需重复创建。每个绑定可开启自然语言派发，直接发送需求开始新任务，用“继续：修改要求”保留上下文；发起人限制和本机权限仍独立。支持手机文字富文本、接收诊断及子进程退避恢复，已确认的收发不重复执行。
- **可播放的网页交付**：HTML 会嵌入经过归属和指纹校验的实际视频，下载后可以离线播放；内嵌媒体总量上限50 MB。Word/PDF 保留视频说明，原 MP4 可单独下载。

实际验收、架构和复现方法见 [2.21 自动协作验收](docs/MODELDESK_221_AUTOMATION.md)。长任务支持以服务声明的 MCP Tasks 扩展为前提；本机运行仍要求 Mac 开机联网，Muse 原生操作仍需要解锁桌面。

## 2.20：可恢复执行、版本化记忆与更清楚的成果

- **关闭桌面后继续执行**：桌面启动独立守护进程，检查网关、执行服务、工作台与 MCP 服务。服务失联时，每项服务 15 分钟内最多尝试恢复 3 次，并保留恢复预算；不会停止健康服务。任务中心显示守护是否在线及需要处理的连接。
- **重启后先核对回执**：任务、代码 Agent、Muse 与 MCP 记录使用私有文件原子写入并刷盘；进程锁在恢复任务前阻止第二个执行服务接管。已确认完成的外部结果只回收，不再次派发；已确认送达的 Muse 会话最多恢复一次原会话观察。未知结果、等待授权和用户停止保持原状态。
- **记忆有版本和来源**：「任务设置 → 任务记忆」展示原始目标、历次修改、底稿、未完成项与统筹整理的验收要求。每个角色的交接绑定同一任务版本和上游输出指纹；最新修改覆盖冲突，原始要求仍完整保留。它是可核对的任务记忆，不代表模型永远不会理解错误。
- **当前可用性不再靠旧标记**：「Agent 与连接 → 项目 Agent」每 30 秒检查执行器、登录、Muse 输入窗口及已配置 API；过去的成功记录显示日期，超过 24 小时不再当作近期验证。选择失联或拒绝凭据的自定义模型时，在创建任务前给出原因。
- **完整阅读与真实文件**：1600px 及以下的界面在对话和成果之间切换，避免两边同时挤窄；更宽的屏幕保留可调分栏。长提问可展开，原文仍能完整复制。内部审查、导出状态放在运行记录中；正文用于呈现用户要求的成品，Word、PDF、HTML 下载入口保留在成果顶部。

真实验收通过 **GPT 作者 → 本机 MCP Agent → Gemini 审稿人** 完成两轮协作及六份文件：第二轮仅修改便签颜色和本轮实际统计数字，其余正文逐字保持；桌面退出后完成交付。第三轮清理内部说明，自动续办一次文稿整理并交付另外三份文件，没有重复调用 MCP。实际停止空闲 API 后，守护在约 4 秒恢复服务，已保存的成果和单次派发回执保持不变。另有故障注入测试覆盖“工具已完成、父任务尚未保存”的恢复边界。

复现命令、对象、数据流与证据范围见 [2.20 可靠性目标与验收](docs/reliability-release.md)。原生 Muse 仍需要可用的解锁桌面；接入任意新 Agent 需要相应适配器，Feishu 实际收发需要用户配置自建应用。此版本没有新增云端宿主或开机自动运行服务。

## 2.19：后台托管、飞书远程与主动交付

- **交代任务后可以离开页面**：群聊“自动完成”默认开启“后台托管”，可在任务设置关闭。执行由本机后台服务持有，切换项目、刷新或关闭聊天窗口不取消任务。
- **安全续办**：持久托管器最多自动继续 2 次，仅重试无工具的模型步骤或复用完成成果进行本地整理、文件排版；已完成步骤保持。外部 Agent、绘图、MCP 状态不确定时保留结果并列入待处理，不重复派发。
- **结果收件箱**：页面顶部“后台任务”可查看当前项目的执行中、自动续跑、成果就绪和待处理任务；未读状态跨刷新保存，可打开准确的历史任务及成果。也可暂停后续自动续跑，当前任务仍可单独停止。
- **主动提醒**：桌面主进程读取已验证的完成/待处理状态并发送系统通知，点击返回具体任务；不在通知中暴露任务正文。关闭窗口仍可提醒；完全退出桌面应用后通知暂停，任务结果继续保存在后台收件箱。
- **恢复与验收**：服务重启后只恢复可证明安全的剩余工作；用户主动停止的任务不复活。完成通知要求当前正文版本、审查、实际媒体与所需文档均通过回读校验。
- **飞书双向入口**：使用飞书官方 SDK 的长连接接收明确的 `/modeldesk` 指令，在绑定项目群内执行；任务状态和成果回到原聊天。App Secret 在本机设置，聊天及可选发起人允许列表控制执行范围；原生应用执行默认关闭，需另行明确授权。消息与发送回执持久去重，无法确认是否送达时保留待处理状态。

Mac 必须保持开机、唤醒和联网，本机服务也需要运行。Muse 原生创作仍依赖解锁的桌面窗口；本次没有新增云端主机、开机服务或周期任务。研究依据和边界见 [2.19 自主协作架构](docs/MODELDESK_219_AUTONOMY.md)。

## 2.18：可核对的记忆与完整 MCP 交接

- **长稿连续修改**：完整稿与一次失败续轮拥有完全相同的正文时，只保存一份正文，以内容指纹引用；仍分别保留两轮状态和来源。不同正文不会合并，任务、群组和项目边界不变。
- **长期记忆不再截断 JSON**：用户选择保存时，保留完整最终结果、原始要求、来源和未完成事项；超过资源上限明确报错。传入模型的工作上下文仍有预算，每份来源显示实际读取字符数、节选或未读取状态。
- **资料选择更清楚**：知识、记忆、MCP 各自显示加载、失败和重试；已选但归档或不可用的资源仍可看见并移除。可展开记忆原文；“上次执行记忆”明确表示上一轮实际输入，不再暗示包含刚产出的结果。
- **MCP 工具完整发现**：读取全部分页工具并检测异常游标；成员设置根据当前允许的工具与参数校验，发现失效或不支持的必要参数时阻止保存。
- **结构化成果完整交接**：保留 MCP 文本和结构化数据，冻结并验证输出 schema；有界结果完整传给后续模型。超大结果明确说明实际已执行，不返回残缺 JSON；同一工具循环不重复派发已明确不可重试的相同调用。

研究依据、复现场景和验收边界见 [2.18 记忆与 Harness](docs/MODELDESK_218_CONTEXT.md)；MCP 协议细节见 [MCP 可靠性](docs/MCP_RELIABILITY.md)。不宣称无限记忆，也不会把工具连通性当作所有外部 Agent 的创作成功保证。

## 2.17：执行成员与文件交付

- **MCP Agent 独立入群**：管理成员中选择已注册服务、获准工具和任务参数。它可以接收完整交接、执行自己的任务，再把真实文本或结构化结果交给下游模型。工具、参数结构和连接版本在派发前冻结，超时或崩溃不会重复调用。
- **自动生成文件**：自然语言要求和明确设置都会进入任务交付契约。支持可编辑 Word、分页 PDF、离线 HTML，以及标准报告、阅读文章、紧凑简报三种版式；标题、段落、列表、表格和已验证图片可进入文档。
- **文件也参加验收**：实际渲染后保存文档及摘要，下载前再次检查归属、字节与正文版本。任一所需格式失败时保留其他文件，并显示部分交付。不能用“已生成”一句话代替文件。
- **版式偏好不会随失败丢失**：文件格式与版式独立保存在本任务记忆里，首次生成失败或继续修改时仍保留；开始新任务会隔离旧设置。
- **文件失败单独恢复**：正文已经审阅通过、仅排版失败时，继续任务只重做文件生成；先核对正文版本、执行记录与真实素材，不重复派发整组 Agent。
- **Muse 权限修复入口**：桌面可直接打开辅助功能设置和定位实际桥接程序。未修改源码或编译工具链时复用已验证桥接，减少无必要的二进制替换；系统授权仍由 macOS 管理。
- **原生交接核对**：Muse 粘贴后使用新的剪贴板标记读取实际草稿，有限等待窗口和复制就绪；正文、会话或焦点不一致时保留草稿并说明具体原因，不重复发送。无声视频要求也不会因为“不需要字幕或旁白”的并列否定被误改为必须配音。

真实验收使用 GPT 作者 → 本机 MCP 分析工具 → Gemini 审稿，自动交付 Word、PDF、HTML；续轮仅修改例子颜色，原有任务与三种文件要求保持。2.17 的 MCP 接入支持同步文本/结构化结果，2.21 增加了 Tasks 扩展；不能把没有适配器的任意应用直接接入，也不能将 xAI 模型 API 称为 Grok Bot 原生应用。详见 [外部 Agent 接入](docs/MODELDESK_217_AGENTS.md) 和 [文档交付架构](docs/MODELDESK_217_DELIVERY.md)。

## 2.16：持续记忆与完整交接

- 任务要求、资料与媒体分别保留：只有媒体而没有正文的成功文件仍可进入后续任务记忆。历史文本附件只携带尚未提供的冻结内容，不再反复加入整包旧资料。
- 原稿沿完整依赖链传递；审核者只写意见时，后续创作者仍收到原稿。无关并行分支不混入，最终汇总和审查不再截掉长稿尾部。
- 展开「分工与执行 → 交接上下文」可核对每位成员的用户要求数量、直接与间接上游、素材引用及指纹。这是准备输入的记录，不代表模型已经理解或成果已通过验收。
- 「任务设置 → 任务记忆」显示要求、历史文本资料和可复用素材；选择新任务时明确提示旧记忆不带入。失败、重启和继续执行仍保留原有任务边界与派发身份。

调研采用 Grok Bot 的持续角色与可见交接思路，参考 LangGraph 的恢复语义及上下文工程研究；没有把 Grok Bot 当作已接入的执行器。详见 [2.16 业务、架构与研究依据](docs/MODELDESK_216_RESEARCH.md)。

## 2.15：更宽敞的群聊与可靠的媒体分工

- 输入区默认只保留任务摘要、资料入口和发送操作。「任务设置」集中管理参与成员、自动完成/仅讨论、成果形式、快捷配方和任务记忆；Muse 原生面板独立打开，执行指令及验收明细按需展开。
- 顶部「成员与分工」可查看角色、添加 Agent 或管理成员；输入 `@` 点名、输入 `/` 选择配方。聊天与成果分别滚动，窄屏打开成果时使用侧栏。
- Harness 支持按步骤声明图片/视频 `output_count`，保留每位成员的配额；数量总和必须与交付要求及复用素材一致。不一致计划先纠正，不静默降低用户要求。老计划没有配额时沿用兼容分配，已保存的继续执行计划不重排。
- Muse 收到自己步骤的实际媒体数量，不再把多视频要求改成一个视频。尚不支持同一图片批次混用 Muse 与独立绘图成员，也不支持同一视频批次混用 Muse 与 Skill 渲染；这类计划明确报错并要求纠正。图片模型与 Muse 视频仍可组合。
- Muse 图片步骤会先收回并校验实际文件，再将图片交给依赖它的后续 Agent；缺图时阻止后续执行。Muse 单步骤最多回收 5 份文件，单次视频请求最多携带 4 张参考图；Lemo Codex 每步骤渲染 1 个 MP4。超出能力的计划必须拆分，不能假装完成。
- 已保存图片/视频独立于最终正文展示：即使汇总失败，也可以预览、下载原文件或导出成果包，状态仍标明部分交付。经来源校验复用的图片保留正文位置，不再误显示为未保存或在图库重复出现。

本次验证范围与操作说明见 [2.15 界面和协作验收](docs/MODELDESK_215_WORKSPACE.md)。

## 2.14：任务记忆与连续交付

- 原始目标、后续修改、最新完整或部分底稿作为独立任务记忆保存。聊天历史窗口即使只保留 1 轮，失败记录和长回复也不会挤掉用户要求；服务重启后可从已保存记录重建。
- 同一项目、同一群、同一任务边界共享记忆；选择「开始新任务」隔离旧目标。输入框上方点击记忆摘要，在「任务设置 → 任务记忆」可核对原始要求、修改顺序、底稿及素材来源。
- 统筹、LLM、绘图角色、Muse 与代码 Agent 使用同一份冻结上下文。用户要求与直接前置定稿完整保留；只有重复背景可以压缩，超出预算时明确停止，不静默裁掉脚本结尾。
- 自动模式的默认配图数不再限制章节数量。「每章一图」按章节安排，单轮最多 12 份媒体，逐张保存；重试只生成缺失图片。可校验并复用当前任务已有的封面，保留来源指纹。
- 持久任务上下文有 60,000 字符上限；超限会明确提示拆分。模型审阅仍可能出错，真实文件检查与内容验收分别记录。
- 2.14.2 修复复核正文中的历史媒体链接：只有与本轮已校验文件来源匹配的旧链接，才映射到本轮副本；桌面和手机均使用各自的服务入口。
- 2.14.1 补齐真实 Muse 跨轮验收：GPT 交接、绑定的 Lemo 指引、Muse 新视频、Gemini 审查和 MP4 回传已经走通。逐项审查必须声明证据覆盖范围，有限或未核实的要求不计作通过；仅缺少检查证据时保留文件，不重复调用 Muse。已校验的历史视频可直接复核，无需再次选择原制作 Agent。

详见 [2.14 Harness 检查与验收](docs/MODELDESK_214_HARNESS.md)。

## 2.12：任务记忆与交付恢复

- 群聊输入区可选「继续本群任务」或「开始新任务」。失败和取消后的用户修改要求会保留，未完成草稿明确标注；新任务边界会持续生效。展开上下文说明可查看实际引用的历史轮次。项目资料仍按显式选择提供。
- 原生 Agent 交接保留完整上游脚本及长度、指纹。Muse 支持最多 22,000 字符的交接正文；超限会明确停止，避免默默截掉故事结尾。
- Muse 的图片预览附件也可自动下载到任务私有目录，最多回收四张关键帧与一个视频。明确标注为 `t=…s` 的视频抽样图不计作独立生成的关键帧。
- 视频模式保留附带关键帧的要求。明确的时长范围、音轨存在性按实际文件检查；缺失文件或这些检查失败时，已确认完成的 Muse 任务最多自动修订一次。只补图片时保留已取得的视频。
- 音轨存在不等于中文旁白内容正确，三个抽样画面也不等于全片字幕同步或人物连续性已经验收。平台继续显示这些核验边界。

## Ruler 与执行 Agent

统筹模型与执行器分别配置。2.10 的「自动完成」直接生成受限依赖计划，调用已保存的模型与实际 Agent，再整理并检查完整交付；没有统筹模型时由所选模型成员负责整理。@ 指定模型不会扩大到其他执行成员。「仅讨论」不派发执行器；两种模式都不能自动批准代码合并。

| 成员类型 | 实际工作方式 | 配置与要求 |
| --- | --- | --- |
| **LLM 模型** | 群内发言、交叉讨论、只读审阅 | 已接入的模型、角色与职责；支持同模型多角色 |
| **Codex Agent** | 在隔离项目副本中编辑文件、运行可用测试、返回补丁 | 官方 CLI 现有登录；可单独指定执行模型 |
| **Claude Code Agent** | 通过受限 CLI 在隔离副本中读写文件 | 支持受限执行的 CLI 版本与可用登录；当前执行路径不提供终端测试 |
| **Muse 应用 Agent** | 操作本机 Muse，保存原生回执与实际读取的回复 | Mac 上安装并登录 Muse，原生桥接和辅助功能权限就绪 |
| **MCP 外部 Agent** | 调用一个已配置任务工具，返回实际文本或结构化结果，交给后续成员 | 已注册 HTTP/SSE 服务、允许列表中的工具、一个字符串任务参数 |

后续讨论可引用同群已完成 Agent 任务的有界输出，并保留任务 ID、执行器、输出与补丁指纹。计划、失败结果和不完整发言不会被当作完整交付。

操作细节见 [统筹模型与执行 Agent](docs/COORDINATOR_AND_AGENTS.md)。

「自动完成」的执行范围、失败处理和成果来源见 [自动交付说明](docs/AUTOMATIC_DELIVERY.md)。它按成员 ID 与类型派发，不把模型发言中的“已完成”当作执行回执。缺少必要图片、文件或运行记录时，仍保存可用正文，并明确标为部分交付。

## 2.11 自动协作 Harness / Goal to delivery

**用户目标 → 验收要求 → 分工与依赖 → 实际执行 → 组合成果 → 检查与修订。** 项目群现在使用 ModelDesk 的自动任务编排；不相关步骤最多两项并行，有依赖的成员收到前一步的实际输出、代码变更和命令记录。

- **目标与上下文保持一致**：保存原始要求、成员副本、准备好的上下文和资料版本；继续执行时发现资料或成员已变更，会要求重新发起任务。
- **完整成果有依据**：检查正文、真实媒体文件、代码补丁与命令记录。最后再对照原始要求检查，防止分工计划遗漏用户需求。优先用不同模型复核；只有一个模型时明确显示自检。
- **有界修订和恢复**：正文可自动修改一次；审查发现 Muse 已完成创作存在具体内容问题时，最多安排一个关联原任务的修订任务。两版成果及其来源保留。未确认送达、失败或中断的原生任务不会自动重发，代码任务不会自动重新执行。停止或部分失败后可继续未完成步骤。
- **媒体内容有检查依据**：审查模型接收已校验图片的缩略图、视频三处抽帧及实际时长；记录文件与抽帧指纹。抽帧不代表已验证音轨或全片连续动作，无法核查的要求仍保留为未完成。
- **成果优先的界面**：右侧仍直接展示最终正文和媒体；验收项、依赖关系和版本可展开查看。缺少必要成果时保留部分内容和明确原因。

每轮初始最多八个步骤、两个并行步骤，可追加一个 Muse 修订步骤，可明确继续两次。普通任务累计二十分钟，含视频任务累计六十分钟，Muse 单次最多观察三十分钟；若最近30秒的同一请求回执确认 Muse 仍在生成且未等待用户，平台在总预算内自动续接一次观察，不再次发送。未知状态、权限确认和用户停止不会自动续接。超时仅结束本地观察，不会重新派发或声称已停止云端创作。自动正文修订每次执行最多一次。当前仍是单机、单后端进程；2.20 的后台守护会恢复服务并续办能够验证安全的工作，未知外部结果仍需检查，尚未提供多机 worker 或跨外部应用的精确一次执行保证。「协作任务」默认进入混合团队自动协作；原有 LangGraph 模板位于「自定义流水线」，与项目群共用资料版本契约，保留各自记录，没有迁移数据库。

业务对象、数据流和代码边界见 [Harness 架构](docs/HARNESS_ARCHITECTURE.md)。

## 图文与视频成果 / Multimodal delivery

2.9 增加 ModelDesk 自己的媒体交付 Harness：**识别成果要求 → 能力路由 → 实际生成 → 文件校验与保存 → 正文排版 → 完整性检查**。例如发送「写一篇给初学者的 AI 编程公众号文章，图文并茂，配两张原创说明图」，平台会生成正文与配图任务，再把真正生成的图片放入文章，而不是只返回配图建议或占位链接。

- **OpenAI 与 Gemini 生图**：复用已有登录网关实际提供的图像模型，或已添加的支持生图的 API 连接。2026-10-15 的本机调用已从 **`gemini-3.1-flash-image`** 与 **`gpt-image-1.5`** 取得真实图片，并通过本地图片校验与保存。「待验证」模型只有在实际生成后才会标为「已实测生图」。这不代表普通聊天模型、任意订阅或兼容 API 都具备生图能力。
- **Muse 图片与视频**：使用当前群内已配置的 Muse 执行成员，在 Mac 上真正派发任务；从本轮确认回复下载真实附件并校验。已实测「正文 + Gemini 图片 + Muse 原生视频」的完整混合交付链，自动保存媒体、组合成果并导出 ZIP。Muse 的文字承诺、网页预览或不相关旧视频不算视频交付。
- **有界恢复与明确选择**：未固定提供方或模型的自动生图，失败后最多再尝试一个不同提供方，总计最多两个；明确选择的提供方不切换。旧失败任务保留部分状态，不会因后来的成功被改写。自动模式支持「Gemini 生成图片、Muse 制作视频」的分别绑定。
- **真实媒体与携带导出**：PNG / JPEG / WebP 使用 Pillow 解码，MP4 / WebM 校验容器并在可用时使用 `ffprobe` 检查视频流。媒体按任务私有保存，读取核对项目范围、大小与 SHA-256。ZIP 包含 `index.html`、`article.md`、实际 `media/` 文件和来源清单，可离线查看；不依赖临时供应商链接。

操作与后端契约见 [图文、视频与媒体 Harness](docs/MULTIMODAL_DELIVERY.md)。供应商官方能力参考：[OpenAI Image generation](https://developers.openai.com/api/docs/guides/tools-image-generation)、[Gemini Image generation](https://ai.google.dev/gemini-api/docs/image-generation)。官方接口能力与本机已验证的适配路径分别记录，ModelDesk 当前不声称完整实现这些接口的全部参数或工具。

## Skills 与绘图角色 / Skills and creative Agents

2.13 将角色路由、实际附件交接和技能执行接入项目群：

1. 在 **Agent 与连接 → Skills** 安装 [Lemo-Opuscar](https://github.com/lemomo-ai/lemo-opuscar)，或导入自己的 `SKILL.md`。
2. 在 **项目 Agent → 成员与分工** 选定角色，勾选 Skill，保存并同步到群。
3. 在项目群选择 **自动完成** 并向全组发送目标。例如：「先由绘图者生成一张纸船插图，再由 Lemo 动画师用它制作 6 秒动画，交付原图和 MP4。」

绘图角色使用所选模型的图像接口。已保存为 LLM 类型的 `gpt-image-*` 会按绘图能力识别；它不会被用作聊天或统筹模型。本机已实测用户网关的 `gpt-image-2.5` 标识返回真实 PNG，此标识是否可用取决于实际连接，不能据此推断官方公共 API 型号。绘图失败不会偷偷换成其他模型。图片与视频步骤建立依赖，真实图片校验后交给 Muse 的原生附件入口或 Codex 的隔离 `film/inputs/`。

**Lemo 执行范围**：绑定到 Codex Agent 时，读取固定版本的导演与风格资料，编写自包含 Canvas/HTML 动画，平台用 Chromium + FFmpeg 渲染 1–120 秒、1280×720、24fps MP4。支持画面字幕和可选 macOS 中文系统旁白。它不是通用写实视频模型，也不继承 Muse 的云端工具。LLM 角色仅使用技能指令；Claude Code 可读取指令，但当前自动动画渲染只支持 Codex。Skills 当前用于项目群和独立代码任务；自定义流程模板遇到 Skills 会明确提示切换到项目群。

**Muse 的 Skills**：在成员编辑器选择「Muse 应用 Agent」，勾选 Skill，保存协作组后应用到当前群。通过群聊「自动完成」或 `@Muse` 派发时，平台冻结该成员的技能版本并随原任务发送。短指令原文传递；长指令及代码渲染技能由本群统筹模型转换为最多 6000 字符的 Muse 创作指引。转换失败或材料过长时停止发送，不截断用户任务、不忽略技能重发。在 Muse 任务卡展开「本次 Skills」可以检查来源版本、指引与送达状态；这不代表在 Muse 中安装上游插件。独立 Muse 面板中未指定群成员的任务不继承群成员技能。

安装不运行第三方 setup/hooks。每轮冻结技能指令和风格参考文件；继续任务复用原版本。自定义导入仅包含 `SKILL.md`，依赖额外脚本或服务的技能需要相应执行适配。新机器的动画依赖：

```bash
uv sync
.venv/bin/python -m playwright install chromium
brew install ffmpeg
```

Muse 回复完成和附件交付分别显示。遇到 `Video not found` 时，保留原始回复和已取得的图片，明确标为视频未交付；可在 Muse 面板点击 **重新回收原会话附件**，不会重新发送创作请求。需要先在 Muse 打开该任务的原会话。

验收记录与已知边界见 [2.13 检查记录](docs/MODELDESK_213_AUDIT.md)。

## 模型连接 / Model connections

- **已有登录**：复用当前本机网关支持的 ChatGPT / Codex 与 Gemini 认证路径。订阅登录和通用 API Key 分开处理。
- **Grok / xAI**：在设置页填写 xAI API Key，读取账户模型列表，选择模型并测试实际调用。
- **其他兼容 API**：配置 OpenAI-compatible Chat Completions 地址、密钥与模型 ID；支持明确启用的本机模型服务，例如 Ollama。
- **凭据隔离**：API Key 只保存在本机后端私有文件中，不返回页面、不写入浏览器存储或任务导出。原生框架 Worker 使用临时、限定模型范围的调用授权。

读取到模型列表或发现登录凭据，不等于实际调用已经通过。界面单独记录调用测试状态。xAI API 接入的是 Grok 模型成员；已有独立 Grok Bot 的云端计算机、记忆和工具不会随 API Key 自动接入。

## 手机访问与执行边界
