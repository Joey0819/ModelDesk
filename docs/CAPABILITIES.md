## 2.6.0：自定义模型连接与动态协作组

左侧导航与设置新增统一「Agent 与连接」面板，分为「项目 Agent」「模型连接 / API Key」和「Muse 应用」三个视图。支持接入 Grok / xAI 官方接口、第三方兼容 OpenAI 规范的 API 以及本机模型服务（如 Ollama）。保存连接后可自动读取服务商提供的可用模型列表，并发送单模型调用测试请求验证连通性。密钥仅保存在本机，绝不进入浏览器或日志；原生 SDK 进程（CAMEL、CrewAI）调用自定义模型时通过短期受限的 Bridge Token 进行内部代理，绝不在子进程环境变量或输入文件中注入真实 API 密钥。

项目群聊现已支持动态应用已保存的协作组配置。群内无活跃讨论或执行任务时，可从群顶部的「管理成员」更新名单与职责分工，并通过乐观锁版本号（`team_revision`）避免并发冲突。历史消息与已交付任务牢固保留当时的成员快照与发言归属，团队变更仅作用于后续新增讨论与任务。同时支持单模型多角色分工，同模型不同职责的成员拥有独立的发言提示与归属。

本轮 327 项自动检查全部通过（后端 208、前端 101、桌面 18），另通过 lint、前端生产构建以及桌面应用 Ad-hoc 严格签名校验。已安装至 `/Applications/ModelDesk.app`，旧版备份至 `llm-tools/releases/backups/ModelDesk-2.5.0-*.app`。实测记录见 `data/validation-images/modeldesk-2.6-connection-test.png` 与 `data/modeldesk-final-2.6.0.json`。

## 2.5.0：独立执行、审批和手机控制

项目群有「持续讨论」「执行任务」「独立审阅」三种入口。独立 CLI 任务保存真实进程事件、隔离副本、基准提交、冻结补丁和退出结果。另一位成员审阅确切补丁后可以创建群内审批卡；明确点击批准才合入本地仓库，分支、基准、路径和补丁变化时拒绝过期审批。不会从审查文字伪造 CI 状态，不推送或合并 GitHub PR。

手机入口使用 Tailscale Serve 私有 HTTPS，网关与 API 都继续只监听本机。一次性五分钟配对码、12 小时 Secure/HttpOnly 会话和设备撤销控制访问；上传、任务状态、群消息和审批使用同源路径。原生 Muse 派发、目录选择和远程访问设置仍在 Mac 操作。实际手机网络验收独立于本机接口和响应式界面验证。

操作及执行器限制见 [独立 Agent 与手机访问](AGENT_GROUPS_AND_PHONE.md)。

## 2.4.0：项目群聊与 Muse

已实现群会话持久化、固定成员、指定成员回复，以及原生 Muse 外部智能体的任务队列、来源记录和显式回复交接。后台测试覆盖项目/群范围、成员快照、异常恢复、发送前保存不确定状态、停止观察、重新观察不重发、回复标记与任务/会话核对。Muse 回复只有满足同项目、同群、送达已确认及回复边界已确认时，才能作为带来源的外部材料加入群任务；引用不会增加工具权限。

本轮 236 项自动检查通过（后端 139、前端 80、桌面 17），另有 lint、生产构建和实际 macOS 应用签名校验。真实 Muse 7.0 原生窗口已完成独立会话派发与回复读回；ModelDesk 界面实际发送 `NATIVE-UI-4245` 并取得原生回复，再通过「使用 Muse 回复继续讨论」交给 GPT/Gemini。另一个任务经单独 @产品经理、下一轮 @技术评审，正确接续 `BLUEBIRD-37`；@所有成员确实分别调用两个模型。记录保存在本机 `data/muse-group-validation.json`，不随 Git 分发。

Muse 当前只接收明确填写的文本，群附件和文件夹不会自动上传。独立任务会话不隔离 Muse 的账户级记忆与连接器；「停止本地观察」不停止云端操作，服务重启和超时不自动重发。部署要求本机 macOS、Muse 安装与登录、辅助功能授权及本地服务，复制应用不能迁移这些条件。详见 [项目群聊与 Muse 指南](PROJECT_GROUPS_AND_MUSE.md)。

## 2.2.0：统一项目与真实多模态资料

顶部「新建项目」在协作、资源、SDK 和原版入口均可使用。普通项目只需名称，已有源码目录仍可绑定。浏览器可通过上传选择器或「关联本地文件夹」预览目录；桌面版提供受主框架验证的固定原生选择器。文件夹先查看清单、明确勾选再复制导入，可再次打开已关联目录追加资料。本轮和共用资料分别管理，切换项目恢复独立草稿与历史，项目最近记录单独查询，不被其他项目的最新记录挤出。

所有九种统一任务使用同一资料层：聊天、Council、CAMEL、CrewAI、接力群聊、Workforce、Flow、代码评审、SDK。当前任务优先于历史资料，图片经校验复制后进入真实多模态请求；当前图片与同项目已完成历史图片共享 8 张/40 MB 预算，保留最初来源任务。连续追问的图片副本可继续继承，移除项目资产登记不改变旧任务副本。新项目/新会话及关闭会话记忆不继承旧图。项目工作说明在任务创建时冻结；共享资料仅在明确标记后默认引用，单轮可以关闭。

项目资源库按本项目/全局/本项目加全局显示，作业拒绝其他项目的附件和知识。保存流程默认继承自身所属项目，并接收当前本轮资料；SDK 模板提供原生图片传输与可核对的派发记录。工具授权与源码快照仍独立选择。ChatHub 原扩展和 MultiBot 原版保留自己的状态与原生功能，工作台不会把本机项目资料自动注入第三方原页面。

## 2.0.1：Workforce 失败处理

规划器接收每个角色实际启用的工具与能力清单，用于约束任务分工；未启用的工具仍不可调用。原生任务失败或最终答复为空时保留失败状态，并保存已生成的步骤、部分输出和原生失败原因。刷新、服务重启及 Markdown/JSON 导出复原这些记录；既有任务也可从其持久事件恢复原生失败信息。

原始研究输出不是有效 `TaskResult` 时，允许同一模型进行一次关闭工具的结构化整理，输入仅为实际任务、近期对话及已执行工具返回的证据。对话证据最多保留 64000 字符、单条最多 12000 字符，截断会标记；整理阶段最多一次模型迭代，输出按严格 JSON/布尔字段与完成标记校验。无效结构或输出截断记为 `structured_output_invalid`；要求没有完成则仍失败，原始文本及格式诊断继续保留，不重放工具或任务步骤。

仅临时传输问题使用 SDK 最多两次重试，任务本身的失败继续报告为失败；不会重放已经执行的角色或工具步骤。页面提供角色工具摘要、运行前检查和编辑后创建新任务的入口，修正配置仍由用户明确选择，不自动启用工具或扩大来源范围。此处理不保证所有工具、任务或外部服务都能成功。

网页工具补充代理假地址兼容：仅非 IP 域名的本机解析结果全部为 `198.18.0.0/15` 时，使用固定 `1.1.1.1` 的 TLS 验证 DoH 查询 A/AAAA，检查所有返回地址均为公网。网页请求固定到验证后的 IP，保留原域名 Host/TLS SNI，关闭该请求对环境代理的隐式继承，并逐次检查重定向；没有修改系统代理设置。[Cloudflare 官方接口](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)、[HTTPX 官方扩展](https://www.python-httpx.org/advanced/extensions/) 本轮已实测读取 [Claude Code 官方概览](https://code.claude.com/docs/en/overview)，HTTP 200、提取 9239 字符。该证据验证公开网页路径，不代表所有网站、原始任务或界面操作都已成功。

## 核心操作

1. 从「快速开始」选择任务或模板，最近成果可直接打开；需要管理智能体、流程、知识或长期记忆时展开高级入口。
2. 在协作任务或流程运行前选择知识文档、记忆空间、项目快照和允许的工具；未选择的资料不会自动进入模型上下文。
3. 「智能体与流程 → 流程库」配置任务依赖、分支、规划和记忆；「原生 SDK 工作室」使用没有专用表单的原生框架 API。
4. 「原版应用」连接并显示完整 MultiBot；ChatHub 保留完整浏览器扩展入口。
5. 从最近会话接续已有任务，或新建独立会话；右侧成果可预览、复制、放大和下载，任务记录保留实际模型、工具结果、分支/跳过原因和历史引用来源。
