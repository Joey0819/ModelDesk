# ModelDesk 2.17 外部 Agent 接入

本版把已注册 MCP 服务的一项任务工具作为项目群的独立成员。统筹模型可以先安排作者整理材料，再让 MCP Agent 执行其职责，最后让审阅成员使用真实返回的结果。工具名、服务器和参数映射由用户设置，模型不能临时选择新的端点或扩大工具授权。

## 操作

1. 在 **项目资源 → 工具与 MCP** 注册 HTTP 或 SSE 服务，发现工具，明确允许本次需要的任务工具。
2. 打开群聊的 **管理成员**，选择 **MCP 外部 Agent**。
3. 选择服务、获准执行工具和接收完整任务的字符串参数名，例如 `prompt`、`task` 或 `text`。点击 **检查 Agent 工具** 验证公开的参数结构。
4. 填写这个成员的职责，可以绑定角色 Skills。选择统筹 LLM，保存协作组后使用 **自动完成**。

服务可以在内部调用自己的 Agent、模型或业务程序。ModelDesk 将全部任务指令、需求和上游实际输出作为一个字符串参数发送；其他必填参数不受此适配器支持。需要多参数的服务可使用 MCP SDK 增加一个专用任务入口，不应让模型构造凭据、端点或任意控制参数。

示例团队成员：

```json
{
  "id": "research_agent",
  "name": "资料研究员",
  "kind": "mcp",
  "model": null,
  "role": "检查交接材料，返回可供作者使用的实际研究结果。",
  "mcp_server_id": "已注册服务的 UUID",
  "mcp_tool": "execute_task",
  "mcp_prompt_field": "prompt",
  "skill_ids": []
}
```

## 业务与数据流

用户配置成员 → 冻结项目群成员及 MCP 连接版本 → 发现指定工具并冻结 JSON Schema → 统筹模型生成有依赖关系的任务计划 → 完整交接文本与角色 Skill 传入指定参数 → 保存一次派发回执 → 调用工具 → 校验实际返回 → 下游成员审阅和整理 → 生成最终文档。

`TeamMember` 保存身份、职责、服务 ID、工具名、参数映射和 Skill ID。`_mcp_agent_snapshots` 冻结连接摘要、Schema 和工具能力；连接地址不会进入公开执行回执。`data/mcp-agent-tasks/` 保存与父任务、项目、群和成员绑定的执行记录。公开 `mcp_receipt` 含工具、Schema 摘要、交接摘要和资源限制说明。

执行前再次核对项目范围、服务器版本、工具允许列表和实际 Schema。调用前先写入 `dispatching`，因此崩溃、停止等待或网络超时不会导致后台重复调用。相同父任务和成员重入时复用同一记录；交接改变时拒绝自动重发。完成输出使用 SHA-256 核验，后续读取损坏的记录不会把它当成完成成果。

## 当前能力范围

- 使用现有 MCP HTTP/SSE 连接，保留连接的项目范围和逐工具授权；此版本没有新增 OAuth 或密钥管理协议。
- 同步调用最多等待 120 秒；完整交接和 Skill 合计最多 22000 字符，实际文本输出最多 80000 字符。超过限制会说明失败，不能静默截断后声称完成。
- 支持 MCP 文本及结构化结果；这是远端服务实际返回，不表示平台已独立验证其中所有事实。
- 图片、音频、资源链接等非文本块不自动下载，也不作为已经交付的文件。与文本一起返回时会明确列出尚未导入的资源；只有非文本块时任务不标记为文本交付完成。
- 服务端异步任务轮询、文件导入、远端取消和专用账号登录需要对应适配器。不能把任何未提供兼容接口的应用直接当作 MCP Agent。
- 保存成员和角色技能不安装原生插件，也不会授权更广的工具或代码执行。

## Grok Bot 和 Muse 的实际边界

Grok Bot 的官方资料描述的是有持续上下文的 Bot、原生群聊与云电脑。公开文档中确认的组织 API 主要用于电脑生命周期管理；inference hooks 用于允许或拒绝推理请求，二者都不是提交工作并获取 Bot 成果的接口。本次检查尚未找到公开的 Grok Bot 任务调用协议。因此，新增 MCP 成员不是宣称已经接入 Grok Bot 桌面账户；xAI 模型 API 连接也不会被标作该原生 Bot。

Muse 继续使用现有原生桥接，其就绪状态来自实际窗口和 macOS 辅助功能检查，不由模型文字推断。2026-11-01 检查时已安装 Muse 10.1，但桥接报告 `accessibility_permission_required`；这是当时的本机状态，后续应以界面重新检查为准。

## 依据与验证

实现复用 [MCP 官方 Python SDK](https://github.com/modelcontextprotocol/python-sdk) 和 [MCP 工具协议](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) 的发现、参数 Schema、调用与错误结果语义。平台选择显式配置单工具入口，以便固定职责和权限。

Grok Bot 接口核查依据：[产品说明](https://docs.x.ai/grok-bot/overview)、[消息与群聊](https://docs.x.ai/grok-bot/chat-and-collaboration)、[电脑管理](https://docs.x.ai/grok-bot/computers)、[推理检查 hooks](https://docs.x.ai/grok-bot/inference-hooks)。文档支持角色持久化和可见交接的产品模式；“没有找到公开任务接口”是对本次查阅范围的结论，不是对所有私有接口的断言。

回归测试覆盖：真实结果与失败结果区分、并发去重、取消和崩溃后的不重放、输入变更、Schema 与连接版本变化、跨项目与允许列表、远端 Schema 引用禁止自动获取、未验证媒体、输出完整性、冻结角色技能、旧成员兼容序列化，以及前端配置保存与成员类型切换。
