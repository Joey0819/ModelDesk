# 自动完成与完整交付

ModelDesk 2.8 将“完成讨论”和“完成用户任务”分开。群聊默认使用「自动完成」；历史记录继续保留原来的模型发言，不会追溯自动派发旧任务。

## 使用方法

1. 在群的成员设置中添加模型和实际执行成员，保存并应用到当前群。
2. 保持「自动完成」与「@协作组」，描述需要的成果和限制，例如“写一篇完整文章”或“调用 Codex 实现功能并运行测试”。
3. 查看时间线中的分工与执行状态。最终正文自动出现在右侧，可复制和下载 Markdown。

普通文字写作不需要为了协作而调用原生应用；需要 Muse、文件修改或真实测试时，调度器只可选择本群已保存的对应执行成员。没有单独选择 Ruler 时，使用本轮模型成员负责调度与整理。只 @ 某个模型不会扩大到其他 Agent。

「仅讨论」保留成员接力与原来的手动交接入口。@ 单个 Codex、Claude Code 或 Muse 仍可明确派发一个独立任务。

## 执行流程

模型讨论 → 受限结构化分工 → 实际执行 → 整理完整正文。

- 分工只接受当前群的成员 ID，每个执行成员最多派发一次。引擎由保存的成员类型决定，模型不能指定新的引擎、权限或合并操作。
- Codex / Claude Code 复用现有隔离副本、凭据隔离和运行限制。原项目不因自动调度而直接修改。
- Muse 复用原生应用桥接，需要匹配的发送回执、会话与回复边界。手机只能执行支持远程入口的模型与代码任务。
- 每个子任务在运行前保存父任务关联。重启不会重放派发；不确定的 Muse 请求不会自动重发。停止父任务会终止其代码任务，或停止本机 Muse 观察，不能保证外部任务已取消。

## 什么会被视为成果

右侧主成果使用独立的最终正文，不再把最后一位成员的建议当成完整交付。整理模型需要逐项列出缺失的必要产物；失败执行、缺少媒体、未确认的原生回复、截断输出或格式校验失败都会保留明确的部分状态。

正文依据本轮实际发言、子任务输出、补丁和来源指纹整理。模型写出的事实与测试总结仍需核对实际记录，完整状态也不等于所有外部事实都已经验证。没有收到图片、视频或文件时，不能以一段“已完成”的文字代替它们。

讨论、真实任务和部分输出继续保留在群中。完整交付可供后续同群上下文复用；未完成正文不会作为已完成交付加入会话历史。明确选择长期记忆时，优先保存正文与交付状态，避免长讨论挤掉最终成果。

代码合入仍需独立审查与人工审批；自动完成不会推送 GitHub、合并 PR 或批准自己的补丁。

2026-10-15 的本机验收已实际完成 GPT / Gemini 讨论后的完整文章交付，以及统筹模型自动派发 Codex、新建两个 Bash 文件、实际运行两个通过用例并整理完整代码与测试结果。原项目保持未修改。命令证据与 CLI 最终自述分开保存，旧任务没有这类结构化记录时不会补造。

## 本机 Muse

Muse 主窗口可能将「New side chat」藏在「Chats」菜单中。桥接会先打开可识别的会话入口，再验证新会话与空输入框；已有草稿、焦点变化、权限请求或无法确认的送达会停止操作并显示原因。它不会清除旧草稿、接管用户原来的对话或用其他模型冒充 Muse 回复。

新版 Muse 的回复操作可以出现在「More options」中。桥接仅在当前任务会话、当前请求之后，且回复带有本次唯一结束标记时接纳这种新结构；辅助功能文本折叠换行时，只恢复标记边界。2026-10-15 解锁后的现场验收已观察到实际发送回执与匹配回复，并进入自动最终交付；锁屏时的先前失败也保留在历史中。此验收证明调用和读取链路，不证明回复中的所有功能宣称或外部动作。
