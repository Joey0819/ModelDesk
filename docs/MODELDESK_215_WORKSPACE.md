# ModelDesk 2.15：聊天空间、真实成果与成员分工

## 业务变化

默认流程是选择项目群、描述完整成果、自动分工、接收实际产物。群内仍可输入 @ 指定成员，或者在任务设置里选择单独派发 Muse/Codex/Claude Code。模型与执行 Agent 的权限及代码合入审批没有扩大。

输入区只保留任务摘要、资料入口和发送操作。参与成员、成果形式、配方、记忆与工具集中到原生 dialog。Esc 可以关闭并恢复焦点。Muse 面板单独打开，状态和历史在后台保留。群聊中长执行指令、验收细节默认收起，完整错误和来源仍可展开查看。

成果保持实际类型：Markdown 文档与表格、代码与补丁、行内图片、媒体画廊、视频播放器、原文件下载及离线 HTML ZIP。没有最终正文但已取得真实媒体时仍展示文件，不合成虚假完成说明，状态保留部分交付。

## Harness 数据与执行

1. 每个媒体步骤可声明严格整数 `output_count`，范围 1–12；这个范围是协议总预算，并不代表每个执行器都能独立完成 12 份。
2. 计划校验按类型计算：各步骤新生成数量 + 已校验复用数量 = 要求总量。未声明的旧计划使用兼容分配；显式配额不改写。继续执行使用已存计划。
3. Muse 单步骤最多回收 5 份文件，视频输入最多 4 张图片；Lemo Codex 每步骤只渲染一个视频。超出限制的计划进入纠正，不减少用户要求。
4. Muse 图片完成后立即回收、校验、保存并挂到该步骤。依赖步骤仅获得经过核对的文件；没有足额真实图片时阻止下游运行。
5. 最终收集器按提供方分别核对图片和视频，避免 Muse 图片加 Skill 视频被误判缺少 Muse 视频。同一类型批次目前不能同时混用 Muse 与独立图片模型，或 Muse 与 Skill 视频；图片模型加 Muse 视频可继续使用。
6. 媒体预览与正文汇总独立，复用图片仍要求精确的来源、任务、项目及文件信息匹配。旧正文中的图片链接映射到本轮已校验副本，不访问任意外部图片。

## 本轮验收

1. **聊天视窗**：在 1280×720 浏览器中，原布局聊天区 220px、输入区约 387px，发送按钮在屏幕外。重构后聊天区约 337px、输入区约 199px；输入框及发送按钮完整可见。开启成果栏时两栏独立滚动。
2. **任务设置**：验证成员切换至 Muse 后显示单独派发；切回全组后恢复自动协作。新任务/继续任务摘要随选择更新，Esc 关闭正常，附件菜单保留图片、文件、文件夹和项目资料入口。
3. **真实媒体**：打开现有已停止且无最终正文的任务，确认其已保存 MP4 仍能加载（readyState=4、时长 6 秒）并实际开始播放；部分交付状态仍显示。此证据证明展示与读取，不代表本轮重新生成视频。
4. **手机布局**：390×844 下无页面横向溢出，导航、聊天、输入框和发送按钮可访问。此项为浏览器响应式验收，不代表真实手机网络重新配对验收。
5. **软件检查**：`scripts/verify_modeldesk.py` 运行 backend unittest、frontend tests、ESLint、desktop tests。新增回归覆盖多角色媒体配额、容量限制、Muse 实图向下游交接、缺图阻断、混合提供方收集、纯媒体成果和复用图片排版。执行器调用使用测试替身，媒体存取用实际本地文件。
6. **打包**：`scripts/package_modeldesk.py` 重建生产页面与真实 macOS App，并校验 bundle 版本、可执行文件和签名。安装及原生验收记录独立保存。

本机截图和机器日志位于忽略目录 `data/acceptance-215/`，不会提交项目内容、缓存或凭据。此次没有新发起付费生图或 Muse 云端创作，不将回归测试解释为所有供应商在线可用。截图与交互检查也不代表全面无障碍认证。
