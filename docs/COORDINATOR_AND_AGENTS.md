# 统筹模型与执行 Agent

ModelDesk 2.8 在同一项目群中区分 LLM 发言者与执行 Agent。成员名称、职责、类型、使用的模型和当前群的统筹设置一起保存；历史任务保留启动时的快照。

## 设置统筹模型（Ruler）

在「Agent 与连接 → 项目 Agent → 成员与分工」，或者群顶部的「管理成员」中，选择「统筹模型（Ruler）」。它可以使用已有登录的模型，也可以选择通过 API 连接接入的模型。

广播到所有模型成员时，工作台实际调用所选统筹模型先给出计划，再依次调用模型成员，最后调用统筹模型形成总结。各阶段在群里显示，结果与调用失败均保存。@ 指定模型成员时只调用该成员，不额外扩大收件范围。未设置统筹时保留原来的成员顺序接话方式。

默认「自动完成」会在讨论后为必要的执行成员生成结构化任务计划，实际调用执行器，收集结果，再单独生成完整交付。用户选择「仅讨论」时只保留原来的讨论流程；也可以 @ 单个 Agent 手动派发。详见 [自动交付说明](AUTOMATIC_DELIVERY.md)。

统筹模型不能通过一句“已批准”合并代码，也不会把任务计划当成已经完成的执行结果。合入项目仍使用人工审批卡；Muse 原生任务需要本机入口授权，手机入口不能调用它。

## 添加不同类型的成员

每个协作组可保存 2–4 名成员，统筹模型单独选择，不占成员名额；LLM 成员与统筹合计最多使用四个不同模型。

| 类型 | 需要配置 | 任务执行方式 |
| --- | --- | --- |
| LLM 模型 | 已接入模型、名称、职责 | 通过模型连接发言；可以参与群讨论与只读审阅 |
| Codex Agent | 名称、职责，可选 CLI 执行模型 | 使用本机官方 CLI 登录，在隔离项目副本中编辑和测试 |
| Claude Code Agent | 名称、职责，可选 CLI 执行模型 | 使用受限 CLI 执行器；具体工具和登录状态以本机能力检查为准 |
| Muse 应用 Agent | 名称、职责 | 通过 Mac 原生 Muse 窗口派发，保存原始回执和实际回复 |

在编辑器的「添加成员类型」中选择类型，再点击「添加 Agent」。LLM 成员选择回复模型；Codex 和 Claude Code 可以留空执行模型，使用官方 CLI 默认设置；Muse 不需要伪造模型 ID 或 API Key。

保存协作组后，需要点「应用到当前群聊」更新已有群。其他群及过去的记录继续使用原来的快照。成员配置变化或有任务正在执行时，过期的应用操作会被拒绝。

## 在群中协作

- @ LLM 成员并发送消息，参与者读取同一群的已完成记录并依次接话。
- @ Codex / Claude Code 成员，填写具体任务后明确派发；实际引擎绑定保存的成员类型。已有模型成员的手动代码执行入口保留兼容，并显示实际使用的执行引擎。
- @ Muse 成员或打开 Muse 面板，检查本机连接后派发任务。原生操作需要在 Mac 上发起，手机不能借群聊绕过原生权限限制。
- 代码任务、补丁、独立审阅和审批卡出现在同一项目群中。后续模型讨论可引用同群已完成 Agent 任务的有界输出；来源包含任务 ID、执行器与内容指纹。过长内容会标记截断。

普通聊天模型不会因为名称叫“代码工程师”而获得文件写入或终端权限；真实执行器的能力、登录和运行限制单独检查。模型专用的旧协作流程对混合 Agent 团队给出明确提示，请在项目群使用这种团队。

## Muse 来源与视频

Muse 的可用状态来自原生桥接检查。原生窗口未就绪、未取得回执或任务失败时，保留该状态，不用其他聊天模型或固定模板冒充 Muse 完成。

历史 ModelDesk 自动生成的创意内容可以保留查看，但标记来源未核实，不作为确认完成的 Muse 回执交给其他成员。视频预览只显示任务关联且有来源的实际资源；不会把同一个示例 MP4 分配给任意新视频任务。旧视频文件和渲染脚本保留，不能据此证明一次新的 Muse 创作成功。

## 验证与打包

运行 `.venv/bin/python scripts/verify_modeldesk.py` 验证后端、前端和桌面策略。运行 `.venv/bin/python scripts/package_modeldesk.py` 重建实际 macOS 应用包并校验签名。
