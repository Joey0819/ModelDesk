# ModelDesk 2.17 文档交付架构

## 业务逻辑

用户描述要完成的工作与结果形式，或在任务设置中选择 Word、PDF、独立 HTML 和版式。统筹模型根据成员实际能力分工；模型、原生 Agent 和 MCP Agent 交换已有任务要求及依赖链里的真实输出。最终正文经过审阅后，由平台自己的排版器生成文件，而不是让文字模型声称已经创建附件。

文件采用标准报告、阅读文章、紧凑简报三种预设。已有任意工作台文本成果也可通过成果面板的「导出」生成文件；独立 Muse/代码任务的原始记录仍保留其 Markdown 导出，将它们放进自动项目群后可统一整理为文档。

## 数据对象

| 对象 | 用途 |
| --- | --- |
| `group_document_formats`、`group_document_layout` | 用户明确选择；格式为 `null` 表示按任务要求自动，空数组表示只在页面显示 |
| `Plan.document_formats`、`document_layout` | 统筹者识别自然语言中的格式与版式；读取输入 PDF 不意味着要求输出 PDF |
| `task_context.document_preferences` | 独立保留同一任务的文件偏好，正文生成失败也不会清空 |
| `delivery.task_spec.documents` | 本轮最终采用的格式、版式与来源；显式设置优先 |
| `delivery.documents` | 当前正文对应的实际文件回执，含格式、版式、大小、SHA-256、正文摘要和下载地址 |
| `delivery.document_errors` | 未能生成的格式及原因；不会伪装成下载文件 |
| `data/delivery-documents` | 每个项目任务的私有字节和清单，独立于聊天正文保存 |

## 数据流转

1. 保存用户本轮要求，载入同一项目、群和任务的持久记忆。
2. 冻结成员、资料、工具与文件设置，构造依赖计划。
3. 执行成员接收完整交接；MCP 派发保存身份、输入摘要和 Schema，已发送但结果未知时不重发。
4. 收集经过归属与哈希检查的媒体及成员实际文本，整理和审查完整正文。
5. 排版器解析 Markdown，生成所选格式。`python-docx` 生成可编辑 Word；隔离 Chromium 将平台生成的 HTML 排成 PDF；HTML 可内嵌真实图片离线打开。
6. 文件落盘后回读校验，把文档结果加入机械验收。任一所需格式失败时标记部分交付，成功文件也保留相应说明。
7. 成果面板展示真实文件下载入口；历史下载保持原版本，改稿后的文件绑定新正文摘要。
8. 如果仅文件生成失败，且正文、审阅版本、依赖执行与媒体仍通过校验，「继续未完成的工作」只重新排版缺失交付，不重新调用模型或执行 Agent。内容发生变化或存在其他缺失项时，仍走正常恢复流程。

## 架构和边界

`coordination.py` 负责任务与验收，`document_delivery.py` 负责交付契约和存储，`document_exports.py` 负责独立渲染。UI 仅提交受支持的格式和版式，不能指定本机输出路径。桌面允许列表只接受固定的导出及任务文档地址，再显示原生保存对话框。

Markdown 使用维护中的 `markdown-it-py` 解析。原始 HTML 按文本呈现；文档渲染禁用 JavaScript、网络、服务工作线程。仅内嵌当前任务媒体库中已验证归属和字节的图片，不抓取外部图片、任意 URL 或本机路径。视频仍从成果面板和成果包播放下载，不假装嵌入可播放的 Word/PDF。

PDF 使用既有 Playwright Chromium，首次部署运行：

```sh
uv sync --locked
.venv/bin/python -m playwright install chromium
```

当前预设面向文字、列表、表格和图片文档；复杂公式、交互图表、幻灯片、任意设计模板以及异步远端 Agent 文件回收需要相应适配器。文档包含实际输出来源与部分完成状态，不能以格式转换补足未完成的内容任务。

## 验证

回归覆盖跨项目下载、路径和符号链接、文件篡改、当前正文与版式匹配、失败格式的部分状态、长文尾部、图片位置、旧媒体链接复用、非法外部资源、真实分页与中文提取。PDF 和 Word 渲染页面还进行视觉检查。

媒体要求同时覆盖「不需要字幕或旁白」「不添加旁白」「不要有字幕」等并列与嵌套否定，并让后续明确修改覆盖先前声明。`audio_required=false` 只表示不强制要求音轨，不等于禁止背景音乐或已经验证成片静音；实际声音状态仍需根据文件元数据及用户要求审阅。

真实两轮验收为 GPT → 本机 MCP `text_statistics` → Gemini → 三种实际文件。第二轮保留任务身份与原始要求，只改例子颜色；六份导出通过 HTTP 下载、MIME、SHA-256、正文和表格检查。统计内容明确指实际交接包，不将其误称为最终稿字数。

可选 Word 视觉验收脚本为 `scripts/verify_document_render.py`：显式加载宿主中文字体，用 LibreOffice 渲染并逐页导出截图，核对原段落与文件摘要。LibreOffice 和 Poppler 仅用于此项 QA，不是产品生成 Word 的运行依赖。最终真实稿的 Word 两页、PDF 一页均完成逐页视觉检查。
