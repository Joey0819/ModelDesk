# ModelDesk 2.19：后台协作与成果收件箱

本版让用户把一个具体任务交给项目群后离开当前页面，再从“后台任务”找回成果、文件和需要处理的事项。后台托管负责观察任务、执行有上限的安全续跑、保存通知状态；实际工作仍由原有的模型、MCP、代码 Agent、Muse 与文档交付链路完成。

## 快速使用

1. 打开项目群，配置角色、模型或 Agent，并选择“自动完成”。
2. 在“任务设置”开启“后台托管”，选择需要的成果形式，例如 Word、PDF、网页或图文文章；也可以直接在任务描述中说明。
3. 发送目标及资料。任务在服务端执行，切换页面、关闭浏览器页面或关闭 ModelDesk 窗口不会取消已经启动的协作。
4. 在项目顶部打开“后台任务”，查看运行中、等待安全续跑、已交付或需要处理的任务。点击“查看成果”返回对应项目群与实际成果。
5. 不想继续自动处理时，选择“暂停托管”。它停止后续自动续跑，已经启动的执行不会因此取消；停止当前执行请进入对应任务操作。

任务与未读状态保存在本机服务。刷新页面后仍可查看；点击“标为已读”只修改阅读状态，不修改任务完成状态，也不会删除成果。

## 后台托管的执行逻辑

```text
用户提交任务及后台托管选择
  → 原有项目群自动完成流程
  → 保存任务状态、执行回执与实际成果
  → 后台托管器检查结果
       ├─ 完整交付：进入成果收件箱
       ├─ 符合安全条件且还有额度：续跑未完成部分
       └─ 外部状态不确定、权限/输入需要处理或额度耗尽：保留成果并通知
```

每项托管任务最多自动续跑 2 次。续跑沿用现有的任务、项目群、冻结输入、角色权限和执行预算；不会因为重新检查而授予新工具、新 Agent 或新的代码合入权限。已经完成的步骤与文件继续复用，代码合入仍经过原有审批。

本版自动续跑的范围是未启用工具的模型步骤，以及条件满足时的正文整理、审查和本地文件打包。未完成的 MCP、Muse、绘图或代码 Agent 步骤进入“需要处理”；最初已获授权的协作仍可正常调用这些能力。这一区分防止后台恢复把一次外部操作变成重复执行。

“安全续跑”不等于重发所有失败调用。对于已经派发、但无法确认结果的外部任务，后台托管应转为需要处理，保留原回执。MCP 的 `retryable:false`、Muse 的不确定发送状态，以及其他不可确认的外部执行，不能靠再次发送来假装恢复。已取得的远端成果也不能仅凭模型的一句话标为完成，仍需通过现有交付检查。

## 状态、数据与通知

业务上区分三件事：任务执行、实际交付、用户是否已读。普通任务的 `complete` 可能包含部分交付，因此后台任务中心以交付结果判断“已交付”，并单独展示需要处理的事项。

后台任务摘要绑定原始任务 ID、项目 ID 和群 ID，包含托管状态、安全续跑次数、更新时间及通知标识。打开任务前核对这些归属，避免切换项目时进入错误的群。通知状态持久保存；前端轮询只是读取状态，不承担执行或续跑职责。

桌面主进程观察本机收件箱，在成果就绪或需要处理时尝试发出 macOS 通知。通知使用概括文字，不把任务正文、资料内容或服务凭据放进系统通知。点击通知回到对应任务。桌面端保存通知尝试记录，避免持续重复弹窗；系统允许通知、桌面应用仍在运行，才可能看到原生通知。没有看到系统横幅不代表任务没有完成，应以任务中心和实际文件为准。

## 运行条件与本版边界

- LLM/API、HTTP/SSE MCP 和不依赖图形窗口的代码 Agent 在后端运行，不需要聊天页面保持可见。
- ModelDesk 原有服务以独立进程启动，关闭窗口不关闭共享服务。后台托管器属于后端服务，不能在后端已经停止时自行执行任务。本版没有新增云端执行、系统开机守护服务或定时任务产品。
- Mac 必须开机、保持系统唤醒、后端与所需网关可用并联网。熄灭显示器与系统休眠不同；本版不修改系统电源设置，也不承诺合盖、关机或休眠期间继续运算。
- 退出 ModelDesk 桌面应用后，仍存活的后端任务可以继续，但桌面主进程退出期间不会发送原生系统通知。重新打开应用后仍可读取持久收件箱。
- Muse 当前通过 `native_ui` 桥接操作现有 Mac 应用，发送与收取需要有效权限、解锁的桌面及可操作的 Muse 窗口。后台托管不绕过这些条件，也不把 Muse 描述为无界面的云端 API。
- 后端重启后必须先核对持久记录和派发回执。恢复观察、恢复明确未发送的工作与重发不确定外部任务是不同动作，不能合并成无条件重跑。
- 本版没有新增 OpenClaw、Hermes 或 Grok Bot 账户接入；已有 Agent 适配器和权限边界保持独立。

## 飞书远程指令与成果

入口是 Mac 工作台的 **Agent 与连接 → 飞书远程**。飞书承担远程消息通道，实际任务仍由 Mac 上绑定的 ModelDesk 项目群执行。使用飞书企业自建应用的机器人与官方 Python SDK 长连接，由 Mac 主动连接飞书，不需要向公网开放本机 API 端口，也不需要配置入站 Webhook 或内网穿透。[官方长连接配置](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)

### 一次性设置

1. 在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用，添加“机器人”能力。普通群“自定义机器人”的推送 Webhook 不能接收用户指令，不能替代这个应用。[官方自定义机器人说明](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot?lang=zh-CN)
2. 根据实际使用范围申请应用权限：发送消息 `im:message:send_as_bot`；单聊接收 `im:message.p2p_msg:readonly`；群内 @ 接收 `im:message.group_at_msg:readonly`；成果文件上传 `im:resource`。如果使用“读取可用群聊”，还需要群信息读取权限。无需为本功能申请以用户身份发送消息、全量群聊历史或通讯录访问。[飞书官方权限治理说明](https://www.feishu.cn/content/article/7615520954977881029)
3. 在 ModelDesk 填写 App ID 和 App Secret。密钥保存后不会回填到页面，不要把它放入任务提示词或 Git 仓库。可先保存凭据并验证，再读取机器人可见的群聊；必要时在飞书把机器人添加到目标群。
4. 在“允许的飞书会话”中填写精确 Chat ID，并选择一个 ModelDesk 项目和项目群。该群应提前配置好协作角色、模型、Agent 与资料。每个飞书会话只绑定一个项目群。
5. 在“发起人限制与本机权限”填写允许的用户 Open ID。**留空表示授权此会话中的所有用户派发任务**；只打算个人控制时，应填写自己的 Open ID。原生 Agent 权限默认关闭，只有确实要从该会话调用 Muse 等本机应用时再开启。
6. 保存并启用连接，保持客户端在线；再到飞书应用的“事件与回调”选择“使用长连接接收事件”，添加 `im.message.receive_v1`，发布应用版本并确认可用范围包含发送者。官方要求保存长连接订阅时已经有客户端在线。[官方订阅设置](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)

如果要绑定私聊但还不知道 Chat ID，可以先启用没有绑定的监听连接，在手机给机器人发一条消息，再回到 Mac 查看最近收到的会话并绑定。未绑定的会话不会创建任务；普通群列表与最近观察到的私聊是不同来源。

### 从手机派发

在已绑定的飞书会话发送文字指令；群聊中先 @机器人：

```text
/modeldesk task 写一份面向初学者的多 Agent 协作指南，包含对照表，交付 Word 和 PDF。
/modeldesk continue 保留刚才的正文和文件格式，把对照表改为四列。
/modeldesk status
/modeldesk cancel 任务编号
```

`task` 创建一项新任务，不自动引用绑定群的历史对话；`continue` 明确使用绑定群的共享上下文提出后续要求。两者都使用该群已有角色，成果保留在 ModelDesk。飞书回传也绑定原会话和原任务；不能通过提示词更换接收者、项目或扩大本机权限。停止或移除绑定用于撤销后续远程处理，不意味着此前已经开始的外部操作可以撤销。

### 验证与回执边界

“凭据验证通过”说明应用凭据可用于相应检查；“长连接在线”说明事件通道已建立。两者都不代表远程任务或文件发送已经完成。首次配置后，应使用自己的允许会话发一项短任务，核对本机只创建一次任务、飞书返回实际状态，并能打开收到的成果文件。没有真实凭据和实际手机消息时，只能记录本地协议与故障测试，不能声称真实飞书收发已验收。

入站消息先持久保存去重回执，外部发送也先记录尝试。对于已经派发但结果不确定的调用，保留状态供核对，不自动重复派发任务或重复发送文件。文件交付与正文交付分开判断，不能把一个上传请求或排队回执写成用户已收到完整成果。

停用或修改绑定会立即更新本机授权，后续派发和发送重新检查这份授权；已经发出的网络请求可能完成，但不会继续发送下一份成果。重复保存完全相同的配置不会撤销现有任务。接收确认消息发送失败也不会取消已创建的任务，最终成果使用独立回执继续交付。“最近指令与回传”展示实际任务与通道状态，查询和帮助指令不会冒充已创建的任务。

正文按顺序分段回传，保留完整文字。Word、PDF、HTML 以及实际图片、视频经过本机归属、版本和哈希核对后，以飞书文件附件回传；图片、视频附件不等于飞书内嵌媒体预览。本通道自行限制单文件为 **20,000,000 字节**。超限或校验失败时保留 ModelDesk 原文件并记录具体交付问题，不截断文件，也不伪造可下载链接。连接状态、任务完成状态和飞书发送回执需要分别查看。

实现复用官方 [`lark-oapi`](https://github.com/larksuite/oapi-sdk-python) Python SDK，核查版本为 [1.7.5](https://pypi.org/project/lark-oapi/1.7.5/)，采用 [MIT 许可](https://github.com/larksuite/oapi-sdk-python/blob/v2_main/LICENSE)。SDK 长连接的 `start()` 占用自己的事件循环，本平台将其与主任务执行隔离；SDK 传输重连不等于任务重跑。Mac 仍需开机、保持唤醒和联网，Muse 原生交互仍需解锁桌面。

### Grok Bot 的产品经验

[Grok Bot 官方概览](https://docs.x.ai/grok-bot/overview)描述了持久角色、共享文件与群内交接，其合盖后继续工作的基础是云端计算机。ModelDesk 本版采用任务和交付独立于聊天窗口的体验，但仍在用户的 Mac 上运行；接入 Grok 模型 API 不等于接入 Grok Bot 的云端 Agent。

[官方 Skills and routines 文档](https://docs.x.ai/grok-bot/skills-routines-and-automations)区分了“如何做”和“何时做”：Skill 保存步骤、输入、验收和审批边界；Routine 由指定 Bot 按日程或事件执行工作流。其建议是先验证单次任务，再固化方法，最后自动化。本版后台托管对应单次已提交任务的监督与安全续跑，没有新增周期 Routine 或 webhook 触发器。官方 webhook 的 `200` 只表示接受并启动，不能当作最终成果回执。

[官方通知说明](https://docs.x.ai/grok-bot/settings-and-notifications)把“正在工作”“需要处理”“未读活动”分开。ModelDesk 同样分开保存执行状态与阅读状态，避免把弹窗、已读或一条对话回复当作交付完成。这些是产品设计参考；本次未复制 Grok Bot 源码，也不将其列为 MIT 开源框架。

ModelDesk 已有自己的项目隔离、协作计划、MCP 回执、原生执行桥接和文档打包逻辑，因此本版在这些边界上增加托管与收件箱，而没有替换成另一套 Agent 运行框架。OpenClaw 的定时调度、Hermes 的云主机部署能力，不因此成为 ModelDesk 的已实现功能。

## 验收应覆盖的产品路径

- 提交一次实际多角色任务后离开页面，服务端继续产生经过检查的成果文件；重新进入项目可找到它。
- 模拟符合条件的暂时失败，确认最多安全续跑 2 次，已完成步骤不重复执行。
- 模拟不确定外部执行、权限失效和用户停止，确认不会重复派发或扩张权限。
- 完整交付、部分交付与未读通知分别保存；已读操作不改变执行结果。
- 桌面关闭窗口后保留任务；通知点击核对任务/项目归属；退出桌面应用期间仍能通过任务中心找回记录。
- 重启后按照持久回执恢复观察，不将已经发送但未确认的外部任务当作新任务重发。

自动测试、真实协作、实际文件与原生通知的验收应分别记录，不能用单项通过推断整个运行环境永远可用。

## 本次验收记录（2026-11-02）

真实后台协作使用 GPT 作者 → 本机 MCP `text_statistics` → Gemini 审稿。提交时 ModelDesk 原生应用未运行，内置浏览器也没有 ModelDesk 页面；任务独立完成后再打开页面。

- 三个角色步骤均完成；MCP 仅派发一次，完整交接包为 11,471 字符、281 个空白分词、27 行，按原始实际输入重新计算一致。
- 自动生成并下载 Word、PDF、HTML；逐份核对 SHA-256、表格、实际统计说明，以及长资料末尾的校验行。PDF 文本提取在中英文之间插入空格，核对时仅规范化提取空白，未改变实际文档。
- 持久收件箱显示“已交付／未读”；从该行打开正确群聊与三份文件，已读状态由服务端保存，刷新后仍保持。
- 故障恢复使用真实协调执行代码和可控模型替身测试：只续跑失败步骤、复用完成前驱、最多两次、服务重启后恢复、用户停止不复活；文档打包失败的恢复不调用模型或 Agent。
- 原生通知的去重、窗口关闭、连接错误页恢复、最新通知目标及预加载交接由桌面回归测试覆盖。是否显示 macOS 系统横幅仍取决于系统通知权限；不把单元测试称为横幅实测。
- 全量验证通过：后端 561 项、前端 190 项、桌面 32 项，以及前端静态检查。飞书通道另使用可重复的本地事件、SDK 请求和故障替身测试，并以本次真实生成的三份文档验证发送前回读。
- 实际浏览器与安装版均已打开后台任务的准确成果；飞书设置页显示“未配置”，聊天绑定与原生 Agent 授权由用户显式选择，密钥未配置时不会连接或发送。

本轮真实调用没有重新触发 Muse 视频创作或图像生成。对这些执行器，本轮验证的是不会在恢复时重复派发的控制逻辑，而非新的云端创作结果。
